# 단계별 과제와 개발 산출물 대응표

2026-09-30. 사수의 과제 구성을 현재 요구사항·기능명세 및 1차 MVP 계획과 연결한다. **과제는 최종 산출물의 구분이고, MVP는 그중 정상 흐름을 먼저 구현하는 개발 순서**다. MVP 시연을 과제1~5 전체 완료로 보고하지 않는다.

출처는 2026-09-04자 「가상 AMR + 관제 시스템 — 신규 채용인원 개발 계획(안)」3페이지의 과제 표와 설명,2페이지의 구성요소 표다. 파일 식별과 전 페이지 판독 기록은 [원문 검토 기록](../evidence/documentation/S029-assignment-review/README.md)에 있다. 기존17페이지 요구사항 PDF와 구분한다.

## 2. GUI와 DataProvider 산출물

원문 과제3은 Mock 실행 화면과 DataProvider 인터페이스를 결과물로 지정한다. 이를 구현할 설계로 GUI에 데이터를 제공하는 Mock/실제 공급자의 교체를 제안한다. 메서드 이름이나 별도 서버를 원문이 지정한 것은 아니다. 논리 계약은 [Core 인터페이스](interface_contract.md)의7절을 사용한다.

- GUI는 같은 데이터·명령 계약을 사용하고 실행 구성에서 Mock 공급자 또는 실제 Core 공급자를 선택한다.
- Mock 공급자는 Broker·실제 AMR·실제 Core·SQLite 없이 재현 가능한 ID·위치·상태 데이터를 제공한다. 현재 공급 모드를 화면에서 구분한다.
- 실제 공급자는 Core의 조회·명령 서비스를 호출한다. GUI와 공급자 어댑터가 MQTT/SQLite를 직접 호출하지 않는다.
- 1차는 목록/위치/상태, MOVE 요청, 요청 결과만 제공한다. Alarm·History·Dashboard 데이터는 해당2차 화면을 만들 때 확장한다.
- M1-01의 Mock 단계에서 MOVE는 비활성화해도 된다. Mock 명령 결과를 제공하면 모의 결과임을 표시하며, 실제 완료 판정에는 사용하지 않는다.

아래3항목은 원문 산출물을 확인하기 위한 **추가 산출물 검증 계획**이다. 기존93개 기능 AC와 별도 식별자로 관리하고 실제 결과는 모두 not_run이다. 관련 GUI 기능 착수 시 추적기 verification과 증거에 연결한다.

| ID | 적용 단계 | 절차 | 기대 결과 | 현재 |
| --- | --- | --- | --- | --- |
| D-GUI-01 | M1-01 | GUI를 Mock 모드로 단독 실행하고 정해진 두 AMR 데이터·좌표 변경 시나리오 적용 | Broker/Core/AMR/DB 없이 마커·ID·선택 상태가 예상대로 표시되며 Mock임을 식별 | not_run |

MVP에는 이3항목과 [M1-AC-01~06](happy_path_plan.md)의 실제 시연 기준을 연결한다. 동일 실행이 양쪽 기준을 만족하면 관측 증거를 명시적으로 연결하여 중복 실행을 줄인다. 기존 전체 기능93AC나 COM-05의7개 검증을 대체하지 않는다.

## 3. 개발 순서와 원문 순서의 차이

원문은 재접속을 과제1에 포함한다. 현재 계획은 정상 연결의 화면 시연을 먼저 만들고 자동 재접속을2차로 미룬다. 이는 사용자가 선택한 구현 순서이며 사수의 납품 순서 변경 승인 여부는 별도다. 기존 재접속 요구를 삭제하지 않는다.

2대·직선 MOVE·AMR당 진행 요청1건·2~3일·DB후순위·WPF Canvas·주기값은 MVP 범위 또는 설계 제안이다. 원문 지정값으로 설명하지 않는다.1차 납품은 정상 흐름 시연, 전체 과제 완료는 이후 전체 범위와 검증을 충족했을 때 구분해 보고한다.

## 4. 사수에게 확인할 두 항목

| 확인 항목 | 현재 계획과 불명확한 점 | 답변에 따른 반영 |
| --- | --- | --- |
| 재접속의 개발 시점 | 과제1 원문에는 포함되지만 현재는 화면 MOVE 시연 뒤2차로 계획 | 원문 순서대로 먼저 완료해야 하면 MVP 일정·순서 조정 |
| 운행 이력의 의미 | 3페이지 개요의2페이지에는 운행 이력이 있으나 데이터 범위·주기는 없음. 현재 상세 명세는 상태/명령/Alarm 업무 이력 중심 | 좌표 시계열·이동 경로 보존까지 필요하면 업무 History와 구분해 저장 범위·주기·보관 기간·조회 명세 추가 |

확인 전 임의로 좌표 이력 저장을 구현하거나 모든 Telemetry를 업무 History에 넣지 않는다. 초기 인메모리 MVP는 두 질문의 미확정 사항과 독립적으로 준비할 수 있다. 전달할 메시지는 [사수 검토 요약](mvp_review_summary.md)의 마지막 절에 있다.
