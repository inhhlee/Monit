# AMR 관제 시스템 개발 작업 목록

[PRD](prd.md)와 [기능명세서](feature_spec.md)를 작업 단위로 나눈다. 2026-09-30 기준 계획이다. 체크된 항목은 기존 검증 기록이 있는 범위이며, 체크박스는 [기능 추적기](../feature_list.json)의 상태를 대체하지 않는다.

## 0. 사용 방법

진행 중 기능을 먼저 이어간다. 현재 in_progress는 없고 다음은 COM-05이다. 제품 구현 전 표준 기준선을 확인하고 한 기능만 활성화한다. 각 Task의 완료 기준과 기능의 전체 검증을 모두 확인한다. 후속 기능의 ID·의존성·정책은 착수 시 추적기에 등록한다.

## Phase 0. 실행 기반과 기존 통신

- [x] TASK-0.1 표준 실행·검증 도구. 완료 근거: 기존 init.cmd/ps1/sh와 S024 기준선. 새로운 PC 검증을 의미하지 않는다.
- [x] TASK-0.2 COM-03 연결·KeepAlive·단절. 완료 기준: revision2의5항목 증거.
- [x] TASK-0.3 COM-04 수신 검사. 완료 기준: revision4의8항목 증거.
- [x] TASK-0.4 COM-01 송수신·독립 큐. 완료 기준: revision4의10항목 증거.
- [x] TASK-0.5 COM-02 생존 감시. 완료 기준: revision2의7항목 증거.

## Phase 1. Command와 ACK 연계

의존성은 COM-01 passing이다. [Iteration01](iteration_01.md)의 유일한 제품 대상이다.

- [ ] TASK-1.1 책임·QoS 계약. 완료 기준: DN-06의 ID 생성·보존·매핑, DN-04 적용 QoS, 대역·CORE-04 제외 범위 기록.
- [ ] TASK-1.2 요청·응답 대역. 완료 기준: AMR2대, 고유 ID, 요청 목록, 역순 ACK 반환과 매핑 관측 가능.
- [ ] TASK-1.3 실제 명령 전달. 완료 기준: MOVE/STOP/RESET의 생성·발행·AMR 수신 ID 일치.
- [ ] TASK-1.4 역순 ACK·필드 보존. 완료 기준: AMR+cmdId로 원래 요청 연결, result/ts/reason 보존.
- [ ] TASK-1.5 실패·불량 ACK. 완료 기준: 유효 FAILURE 전달, ID 누락/타입 오류 ACK 거부·원인 로그.
- [ ] TASK-1.6 증거·회귀. 완료 기준: COM-05의7항목, 표준 기준선, 영향 회귀, 전체 추적 기록과 종료 검사 통과.

## Phase 2. 통신 복구

COM-05 다음 제안이며 INT-04 전체 완료와 구분한다.

- [ ] TASK-2.1 복구 계약. 완료 기준: P-05의 재시도·중지·세션 초기화·구독 복구·미완료 명령 정책과 revision 영향 기록.
- [ ] TASK-2.2 관제·AMR 재접속·재구독. 완료 기준: Broker 재시작 후 프로그램 재실행 없이 새 Heartbeat/명령/ACK 수신.
- [ ] TASK-2.3 실패·종료. 완료 기준: 실패 원인 관측, 중복 소비자 방지, 취소 후 재시도 중지, 이전 세션 격리.

## Phase 3. 가상 AMR 설정과 이동

설정과 상태 전이를 먼저 정의하며 관련 기능을 하나씩 활성화한다.

- [ ] TASK-3.1 설정 기반2대. 완료 기준: 고유 ID·시작 위치/속도/경로, 불량 설정 거부, 상태 독립.
- [ ] TASK-3.2 상태·ACK 의미. 완료 기준: P-02/03/07의 명령 허용 상태·도착 오차·중단 결과·Telemetry 주기 명시.
- [ ] TASK-3.3 MOVE·Telemetry. 완료 기준: 실제 계산 위치·속도·상태와 수신 값 일치, 도착 후 실제 성공 ACK.
- [ ] TASK-3.4 STOP. 완료 기준: 정지 후 좌표 고정, STOP과 원래 MOVE 결과를 정한 정책대로 각각 확인.

## Phase 4. 장애와 Alarm

- [ ] TASK-4.1 장애 정책. 완료 기준: P-04의 코드·심각도·원인·이동 제한·해제 조건·전이 정의.
- [ ] TASK-4.2 발생·해제 발행. 완료 기준: 실제 장애와 ACTIVE/CLEARED 수신 일치, 두 AMR 장애 독립.
- [ ] TASK-4.3 명령 거부·RESET. 완료 기준: 이유 ACK, 원인 지속 복구 실패, 원인 해소 후 정해진 복구.

## Phase 5. Core와 저장소

- [ ] TASK-5.1 등록·현재 상태. 완료 기준: P-06 미등록/미수신/Timeout 정책, 통신·운행 상태 분리.
- [ ] TASK-5.2 실제 업무 요청·결과. 완료 기준: P-08 중복·미요청·타 AMR·늦은 ACK·미수신 정책과 조회.
- [ ] TASK-5.3 SQLite 이력. 완료 기준: P-09 스키마·보관·실패 정책, 재시작 조회. 검증 로그와 구분.

## Phase 6. GUI와 통합

- [ ] TASK-6.1 화면·Core 인터페이스. 완료 기준: 목록·상세·명령·Alarm·History 화면, 요청/응답·갱신 방식 명세.
- [ ] TASK-6.2 표시·조작. 완료 기준: GUI가 Core를 경유하고 상태·결과 일치, Communication/SQLite 직접 접근 없음.
- [ ] TASK-6.3 통합 시연. 완료 기준: SC-001~006을 실제 가상 AMR/Core/GUI/DB로 수행, 대역 시험과 별도 증거.

## 전체 완료 기준

포함 기능의 현재 revision 검증, 표준 실행, 실제 MQTT·통합 시나리오를 통과해야 한다. 코드·설계·추적기·진행 로그·증거가 일치해야 한다. COM-01~04 passing이나 이번 문서 구성이 전체 제품 완료를 의미하지 않는다.
