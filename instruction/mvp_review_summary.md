# AMR 관제 시스템 1차 MVP 검토 요약

2026-09-30. 전체 요구사항의 구현에 앞서 MQTT 통신과 WPF 화면 제어를 연결하는 1차 개발 범위다. 사수 검토용 초안이며 승인·구현 완료를 의미하지 않는다.

## 목표

가상 AMR 2대의 위치를 WPF 마커로 표시하고, 화면에서 MOVE를 요청하면 실제 가상 이동과 도착 결과까지 확인한다. 기존 MQTT 연결·입력 검사·AMR별 큐·Heartbeat 감시는 재사용한다.

## 1차 개발 범위

- 서로 다른 ID·초기 좌표를 가진 가상 AMR 2대 실행.
- MQTT Telemetry를 Communication → Core → WPF로 전달해 마커 위치 갱신.
- 로봇 선택·목표 X/Y 입력·MOVE 요청.
- 가상 AMR 직선 이동, 도착 후 같은 cmdId의 SUCCESS ACK와 화면 완료 표시.
- 두 AMR 독립 동작·정상 재시작·실행 절차와 검증 기록.

1차는 DB 저장 없이 인메모리로 동작한다. 정상 연결·유효 MOVE·AMR당 진행 요청1건 조건으로 시연한다. 명령 수신 즉시 성공을 반환하지 않는다.

## 일정과 완료 기준

집중 개발2~3일, 여유 포함14~20시간을 목표로 한다. 현재 개발 환경과 C#·WPF·MQTT 이해를 전제로 한 추정이며 환경 복구나 요구 추가 시 재산정한다.

| 작업일 | 산출 결과 |
| --- | --- |
| 1일차 | 최소 마커 화면과 실제 AMR Telemetry·Core 상태 |
| 2일차 | 실제 좌표 표시와 화면 MOVE·도착 결과 |
| 3일차 | 두 AMR 독립 시연·재시작·회귀 검증·실행 안내 |

완료 기준은 실제 가상 AMR2대·Broker·Core·WPF를 연결해 각각의 이동과 명령 결과를 관찰하는 것이다. 임시 화면 데이터나 시험용 성공 ACK만으로 완료 처리하지 않는다.

## 2차 개발 범위

SQLite·명령/상태/Alarm 이력, STOP/RESET, 업무 명령 Timeout·중복/지연 처리, 자동 재접속·재구독, Alarm·장애·복구, 영속 장비 등록과 전체 Dashboard/지도 상세를 확장한다. COM-05 남은 전체 검증도 별도로 마무리한다.

## 검토 요청

위 범위로 1차 시연을 먼저 진행하고 이후 전체 요구사항으로 확장하려 한다. 1차에 반드시 추가해야 할 기능, 시연 일정 또는 우선순위 조정이 필요한지 검토를 요청한다. 아직 외부로 발송하지 않았다.

최종 범위는 [요구사항 정의서](prd.md), 구현 순서와 세부 시연 기준은 [1차 MVP 개발 계획](happy_path_plan.md)을 참고한다.
